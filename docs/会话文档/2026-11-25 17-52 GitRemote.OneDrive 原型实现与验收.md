# 2026-11-25 17:52 GitRemote.OneDrive 原型实现与验收

本轮从重置后的原型骨架实现了 OneDrive Git Remote Helper、仓库管理命令和系统测试。原型使用 Windows 上的 .NET 11 和原生 Git。正式项目 `GitRemote.OneDrive` 保留当前提交中的骨架。 [原型使用说明](../gitremote-onedrive-prototype.md)

## 项目结构

| 项目 | 职责 |
| --- | --- |
| `GitRemote.OneDrive.Prototype.Cli` | 生成 `git-onedrive`，提供登录、退出、专用目录配置、建仓、列表、地址查询、GC、状态和恢复。 |
| `GitRemote.OneDrive.Prototype` | 生成 `git-remote-onedrive-prototype`，处理 Remote Helper 协议并接入原生 Git 服务。 |
| `GitRemote.OneDrive.Prototype.Core` | 共享认证、Graph 文件访问、Git 对象传输、引用发布和维护逻辑。 |
| `GitRemote.OneDrive.Prototype.IntegrationTests` | 存放原型系统测试、真实 OneDrive 验收和测试宿主。 |

两个应用各自引用 Core，可独立构建并发布到同一目录。原有 Graph 验证保留在独立的集成测试项目中。 [解决方案](../../GitRemote.slnx) · [原型验收入口](../../tests/Verify-OneDrivePrototype.ps1)

## 仓库和传输

- 一个个人 OneDrive 账号可管理多个仓库。专用目录默认是 `GitRepositories`，目录设置随账号同步。管理命令和仓库地址均可省略 `.git`。建仓和列表输出包含完整目录的地址，设备间可直接复用。仓库支持 SHA-1 和 SHA-256。
- 默认直传使用原生增量 pack，Fetch 只下载补齐缺失对象所需的 pack。智能传输使用原生 Git 服务，支持浅克隆、部分克隆、远程归档和签名推送。无状态入口提供 Git v2 读取。 [传输模式](../gitremote-onedrive-prototype.md#git-传输)
- OneDrive 保存可直接复制和克隆的原生裸仓库。Push 验证对象后，以 ETag 条件替换 `packed-refs`。同引用竞争会校验原预期值，不同引用更新可在重新验证后合并。原子推送通过一次引用发布生效。
- GC 默认预览，应用时使用原生 Git 的对象保留策略。显式 `--prune=now` 可立即回收不可达对象。替代 pack 先校验并发布，再在独占维护期间按记录清理旧文件。操作日志和会话登记用于核对中断结果并隔离迟到的请求。

## 验收结果

- 最终模块拆分后，解决方案构建成功，两个不同的可执行入口可发布到同一目录，旧管理选项可转发给 CLI。原型项目的 26 项离线系统测试通过，真实 OneDrive 用例在这轮离线验证中跳过。
- 模块拆分前，4 项真实 Graph 检查通过，覆盖条件写入、同名创建、版本变化和跨客户端回读。真实 OneDrive 端到端流程完成建仓、Push、Clone、增量 Fetch 和 GC。GC 前后直接下载的原生仓库均通过 `git fsck --full` 和原生克隆。测试目录均已清理。
- 真实验收发现目录同名冲突可返回 HTTP 412。能力探测接受已验证的冲突状态，并回读核对源与目标目录身份。传输对发送请求前的 TLS 握手失败做有限重试。 [端到端验收用例](../../tests/GitRemote.OneDrive.Prototype.IntegrationTests/SystemTests/LivePrototypeTests.cs)
